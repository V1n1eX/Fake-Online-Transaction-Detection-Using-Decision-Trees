Project overview

Fake Online Transactions Using Decision Trees

1. Project Overview

This project studies online transaction fraud by training a machine learning model to separate normal users’ financial activity from suspicious behavior. The repository contains a Django web application and a trained Random Forest model that serves as an academic demonstration of fraud detection using transaction features.

2. Problem Statement

Fraudulent online transactions can appear similar to legitimate payments, making the task difficult for rule-based systems alone. The project addresses this challenge by learning patterns from transaction histories and producing automated classifications.

3. Objectives

  • Analyze transaction features that may indicate suspicious behavior.
  • Prepare the dataset for model training and evaluation.
  • Train and validate a fraud detection model.
  • Build a simple Django interface for transaction screening.
  • Present the work in a professional project portfolio.

4. Dataset

The project uses the dataset stored in dataset/onlinefraud.csv. The repository metadata shows the dataset includes 76,927 total rows, with 107 fraud cases and 76,819 legitimate cases.

The dataset is highly imbalanced, and the project notes this clearly in the README and model evaluation files rather than presenting misleading results.

5. Data Preprocessing

The project prepares the data by dropping rows with missing target labels, separating numeric and categorical variables, imputing missing values, and converting categorical fields into a format the model can process.

This pipeline is implemented in the project’s machine learning module and keeps the preprocessing and model logic consistent for training and prediction.

6. Decision Tree Algorithm

The core model is a Random Forest classifier, which is an ensemble of decision trees. This model is well suited for classification problems where patterns are non-linear and relationships between features are complex.

Random Forest was selected because it can handle transaction data, work with mixed feature types, and provide a practical classification output for fraud screening.

7. Model Training

The training flow uses a stratified train/test split with a test fraction of 0.2 and random state 42, as recorded in the project evaluation metadata. The project stores the trained model artifact at models/random_forest_model.pkl.

The repository also contains evaluation results in results/model_metrics.json so project progress and model performance can be reviewed directly.

9. Evaluation / Results

The recorded evaluation values in the project metadata are:

  • Accuracy0.99896
  • Precision1.00000
  • Recall0.23810
  • F1 score0.38462

The project documentation explicitly notes that the dataset is imbalanced and that the high accuracy should not be treated as proof of strong fraud recall. Detailed results are kept in the repository for review.

10. Django Application

The repository includes a Django web application for user interaction and model-driven transaction assessment. The application presents a form where users can enter transaction attributes, loads the trained model, and returns a classification outcome alongside a risk signal.

This keeps the machine learning backend and the user-facing interface separated, while allowing the project to be reviewed and used in a university demonstration context.
